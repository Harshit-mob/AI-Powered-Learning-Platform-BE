# Project File & Content Structure

This document outlines the scalable folder architecture for the AI-Powered Micro Learning Platform backend. It is designed to cleanly separate FastAPI application logic from physical content, generated AI artifacts, and temporary storage.

## Root Directory Structure

```text
backend/
├── app/                  # (Existing) Clean Architecture FastAPI application
├── content/              # Immutable Source of Truth for learning materials
├── generated/            # AI-generated JSON outputs and structured data
├── storage/              # Ephemeral and user-uploaded files
└── logs/                 # Application and pipeline execution logs
```

## 1. Content (`content/`)
**Purpose**: Stores original, immutable learning content.
**Scalability**: Structured hierarchically by `board/grade/subject/chapter`.
**Best Practices**: 
- Never modify files inside this directory programmatically.
- Always accompany raw content (e.g., `chapter_1.pdf`) with a `metadata.json` file to inform the pipeline.
**Expected File Types**: `.pdf`, `.epub`, `.docx`, `.png`, `.json`, `.md`

## 2. Generated (`generated/`)
**Purpose**: Acts as an intermediate holding zone for data generated by the AI Pipeline before it is persisted to PostgreSQL, or as a cache for expensive AI operations.
**Folders**:
- `extracted_text/`: Raw text dumped from PyMuPDF.
- `cleaned_text/`: Text processed by the Cleaner service.
- `parsed_curriculum/`: JSON representing the structural hierarchy.
- `learning_units/`: Granular micro-concept JSONs.
- `question_bank/`: The final AI-generated assessments.
- `validation_reports/`: Logs of failed Pydantic validations during AI generation.
**Expected File Types**: `.json`, `.txt`

## 3. Storage (`storage/`)
**Purpose**: Handles temporary processing and dynamic file storage.
**Folders**:
- `uploads/`: For handling future dynamic user or admin uploads via the API.
- `temp/`: Used by the Content Pipeline for ephemeral operations (e.g., saving a page as an image to pass to OCR).
- `exports/`: Destination for downloadable reports, CSVs, or compiled offline packages.
**Expected File Types**: Any format. Files here are considered ephemeral or safely deletable.

## 4. Logs (`logs/`)
**Purpose**: Persistent storage for application logs (e.g., Uvicorn logs, AI Provider latency metrics, pipeline error tracing).

---

## Configuration Best Practices
- **No Hardcoded Paths**: The backend application must resolve these directories using relative paths configured in `app/core/config.py` (e.g., using `pathlib.Path(__file__).parent`). 
- **Environment Driven**: Allow overriding these base directories via environment variables (`.env`) for production deployments where storage might be mounted on external volumes.
